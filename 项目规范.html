02

开发环境配置

搭建本地开发环境到各平台调试

基础环境

📦

Node.js 18+

推荐 20 LTS

⚡

pnpm

npm install -g pnpm

📘

TypeScript 5.8+

随项目依赖安装

安装依赖 
pnpm install

Electron 端依赖在 electron/ 目录通过 electron/package.json 管理，由构建脚本 install-deps 步骤自动安装。

浏览器端开发

最快速的调试方式，适合日常 UI 与逻辑开发。数据通过 Capacitor Filesystem Web 兜底实现存储到浏览器 IndexedDB。

npx vite
调试技巧
  • Chrome DevTools（F12）断点调试、查看 Network 与 IndexedDB
  • 安装 Vue DevTools 浏览器插件查看组件树与 Pinia 状态
  • Vite 自动热更新（HMR），无需手动刷新
  • 浏览器端无法调试 Electron 主进程，需在 Electron 环境中验证

Electron 端开发

通过内置 Express 服务器提供 API，数据存储在 app.getPath('userData')/data/。

pnpm build
npx electron electron/main.cjs
调试技巧
  • 主进程日志输出到终端与日志文件 userData/logs/app-YYYY-MM-DD.log
  • 渲染进程可通过 mainWindow.webContents.openDevTools() 打开 DevTools（生产已禁用）
  • 修改主进程代码后重启 Electron 生效

Android 端开发

pnpm build
npx cap sync android

然后用 Android Studio 打开 android/ 编译运行。

注意事项

  • 浏览器端与 Electron 端数据存储相互隔离，不互通
  • vite.config.ts 中 base: './' 确保打包后资源路径正确，请勿修改
  • virtual:version 虚拟模块在构建时从 package.json 注入版本号

技术架构

前端技术栈与跨平台方案

前端框架

  • Vue 3 + Composition API + TypeScript
  • Pinia 状态管理
  • Vue Router 路由
  • Element Plus UI 组件库

3D 可视化

  • Three.js 渲染地球、月球、太阳
  • NASA 真实卫星图片纹理
  • Canvas 流星粒子动画
  • MeshPhongMaterial 含 fallback 色 #2a6f97

编辑器与图表

  • 自研 Markdown 编辑器 — 通用组件（笔记、日记共用）
  • ECharts — 统计图表
  • lunar-javascript — 农历计算

跨平台方案

  • Electron — Windows 桌面
  • Capacitor — Android

主进程能力（IPC）

  • 渲染进程与插件不得直接使用 Node 能力（contextIsolation: true / nodeIntegration: false），所有系统能力统一由 electron/preload.cjs 挂到 window.electronAPI，实现放在 electron/main.cjs 的 ipcMain.handle，类型在 src/types/electron.d.ts 同步声明（三处需一并修改）
  • execPowerShell(command) — 执行 PowerShell 命令；stdout/stderr 经 powershell-output 事件流式回推，渲染端用 onPowerShellOutput(cb) 订阅、offPowerShellOutput() 取消订阅（组件卸载时必须取消）；主进程已统一 UTF-8 输出编码
  • startSnowbaby(payload) / stopSnowbaby() — snowbaby 常驻进程管理（IPC：snowbaby-start / snowbaby-stop）。主进程用 child_process.spawn('node', ['app.js']) 直接启动并注入 ESD_DATA_DIR 环境变量（不再用 PowerShell Start-Process 后台启动），捕获其 stdout/stderr 实时经 powershell-output 事件回推渲染进程；停止时用 taskkill /T 递归终止整棵进程树
  • napcatGetStatus() / napcatDownload() / napcatInstall() / napcatStart(payload) / napcatStop() / napcatUpdate() / napcatUninstall() — NapCat Shell 手动版管理（IPC：napcat-get-status 等）。仅适用 Windows AMD64（process.arch === 'x64' 检测）。下载：从 NapCatQQ GitHub Releases 最新版获取 NapCat.Shell.zip（https.get 取 tag/资产 URL，net.request 下载到 data/<用户ID>/napcat/）；QQ 检测：detectQQ() 遍历常见安装路径（%LOCALAPPDATA%\Programs\Tencent\QQ、%LOCALAPPDATA%\Tencent\QQ、C:\Program Files\Tencent\QQNT 等）以及用户持久化的 napcat_qq_dir（localStorage）指定目录，用 findQQExe 在根目录/versions 子目录找 QQ.exe，版本号优先从 versions/<版本号> 目录名提取（如 9.9.32-51246），回退 resources/app/package.json；安装：PowerShell Expand-Archive 解压；启动：按 os.release() 判断 Win10（build < 22000），在解压目录运行 launcher-win10.bat（Win10）或 launcher.bat（Win11），可传 QQ 号参数快速登录，主进程 spawn('cmd', ['/c', ...]) 捕获 stdout/stderr 实时回推；停止：taskkill /F /IM QQ.exe /T（手动版基于 QQ 运行）；更新：重下并解压覆盖（先停止进程）；卸载：终止进程并 fs.rmSync 删除目录
  • openDirectory() — 打开系统目录选择对话框（dialog.showOpenDialog 的 ['openDirectory']），返回所选目录路径；用于 NapCat 区域让用户手动指定 QQ 安装目录
  • napcatCheckQQ(dir) — 检测用户指定的 QQ 安装目录（IPC：napcat-check-qq），复用 detectQQAt 找 QQ.exe 并读版本，返回 { installed, path, version }
  • httpGetJson(url) — 由主进程发起 HTTPS GET 并解析 JSON。访问第三方接口一律走此通道，渲染进程直连会被同源策略拦截
  • httpGetText(url) — 由主进程发起 HTTPS GET 并返回原始文本 {status, text}。插件市场下载 GitHub 源文件（README、plugin.json、源码等）统一走此通道，返回的 status 用于判断 HTTP 状态；主进程 https.get 已带 User-Agent，避免渲染进程 fetch 因同源策略/网络波动导致 Failed to fetch 或超时中止

插件系统架构

  • 插件仅支持 Electron 端，以源码形式分发（插件市场从 GitHub 仓库下载源码），不打包进 exe
  • 开发模式：src/lib/pluginLoader.dev.ts 通过 Vite glob 加载 src/plugins/<插件ID>/，随主应用一起编译
  • 生产模式：插件安装到 userData/plugins/<插件ID>/；应用启动时主进程用 esbuild 将每个工具打包为单文件 ESM（dist/<工具ID>.js），渲染端经 Express /api/plugins/<插件ID>/dist/<工具ID>.js 动态导入，重启后生效
  • 运行时桥：共享依赖（vue / pinia / element-plus / 应用内部模块等）不打包进插件产物，由 src/lib/pluginBridge.ts 暴露到 window.__ESD_BRIDGE__，保证插件与主应用共用同一 Vue / Pinia 实例
  • 桥接白名单：插件可引用的模块受白名单约束，在 electron/build-plugin.cjs（BARE_BRIDGE / SRC_BRIDGE）与 src/lib/pluginBridge.ts 两端登记，新增可桥接模块需同步修改两处。白名单键名必须与插件内实际 import 路径一致：例如通用对话框键为 components/ui/BaseDialog.vue（组件已从 components/common/ 迁移至 components/ui/），components/common/BaseDialog.vue 仅作为历史别名保留以支持未重新编译的旧插件产物
  • 编译标记 dist/.compiled 内容版本化（main.cjs COMPILED_TAG），打包器变更时递增，强制已安装插件重编译
  • Electron 运行时依赖（electron/package.json）：@vue/compiler-sfc（SFC 编译）、esbuild（打包），经 extraResources 随安装包分发
<插件ID>/
├── plugin.json              # manifest + tools 元数据
├── index.ts                 # 仅开发模式（Vite glob）使用
├── tools/<工具ID>/index.vue  # 工具组件（script setup）
└── dist/                    # 生产模式启动时自动生成的打包产物
    ├── <工具ID>.js
    └── .compiled            # 编译标记（内容 = COMPILED_TAG）

UI/UX 规范

视觉风格、布局与交互约定

视觉风格

配色

深色星空背景、蓝紫渐变 #667eea、琥珀强调 #fbbf24

文字

rgba 白色透明度梯度，深色背景下 clear 可读

布局规范

  • 面包屑地址栏导航，支持下拉快速切换模块
  • 卡片网格布局，响应式列数（全局最多 6 列；清单页、倒数日页、课程表列表视图例外：最多 3 列、卡片间距与左右边界留白均为 25px，见 ListPage.vue / CountdownList.vue / CourseSchedule.vue）
  • 支持分屏显示（左右双面板）

交互规范

  • 卡片右上角 hover 显示操作按钮
  • 下拉菜单使用固定定位 + backdrop-filter 模糊背景
  • 确认操作使用 ConfirmDialog，消息提示使用 ElMessage

3D 场景层级

层级顺序

Canvas 流星画布的 z-index 必须低于 Three.js 元素（地球、月球、太阳），避免遮挡。

笔记幻灯片内容区

  • 幻灯片内容区去除深色背景，融入星空主题，文字浅色
  • 代码块通过"插入 HTML 代码"按钮插入，编辑/预览/放映态均语法高亮
  • 原生 pre 块自动语法高亮与格式化缩进，使用 src/utils/codeBlock.ts 的 highlightCodeBlocks / serializeCodeBlocks，编辑态保存前需调用 serializeCodeBlocks 还原纯文本
  • 主工具栏在未选中文本时禁用字体、字号、加粗等按钮，通过 hasSelection 控制
  • 下划线按钮为单按钮（点击展开下拉、不直接应用），提供 8 种线条样式与颜色设置；颜色选择器通过 Teleport 浮动到 body
  • 复制样式/应用样式按钮在主工具栏，样式保存至 data/用户ID/notes/style.json；仅当前编辑会话有效，离开时清空
  • 粘贴内容提供"保留源格式"和"只保留文本"两个选项
  • 致谢页通过右键导航栏的致谢页项，在幻灯片菜单中选择"修改致谢内容"弹窗编辑

组件使用规范

组件组织与常用组件说明

组织规则

  • 组件按功能模块组织在 src/components/ 下
  • 通用组件放在 common/（nav、card、overlay、picker）
  • 页面组件以 Page 结尾命名（如 NotesPage.vue）

常用组件

组件说明
MainNav全局导航栏（桌面端/移动端/Android/拆分面板）。桌面端采用左侧导航区 + 右侧内容区布局（variant="left"），导航项以「图标在左、文本在右」排列（宽度 120px），导航栏底部提供收起/展开按钮（toggle 事件 + collapsed prop，收起后仅显示图标窄栏）；移动端/Android 仍为底部导航栏（variant="bottom"，距页面下边界 25px 透明浮层，图标在上、标签在下）；交互：单击导航项切换页面，长按左键（约 0.3 秒）进入滑动模式可左右滑动（通过 pointerdown/move/up + setPointerCapture + 长按计时器实现，长按/滑动会抑制随后的点击；拆分的 variant="split" 同样支持，flex-start 布局便于溢出滚动）；导航项末尾提供「拆分」入口（进入/退出拆分界面，通过 split 事件与 splitActive prop 控制）；拆分界面下每个面板采用「顶部内容区 + 底部导航区」布局（variant="split" 改为 in-flow 撑满该面板宽度，不再为固定 500px 浮层），拆分项文案随 splitActive 变为「合并」。拆分功能从右键菜单迁移至导航栏，原右键菜单已删除

构建与部署规范

各平台构建命令与部署流程

Windows

pnpm electron:build:win

清理 → vite build → 安装依赖 → 生成图标 → electron-builder → 修复 latest.yml

Android

通过 Android Studio 打开 android/ 目录，执行 Gradle 构建。

应用图标构建

图标由源文件 build/app-icon.png 通过构建脚本自动生成各平台所需尺寸。

build/app-icon.png（源文件）
  │
  ├─► scripts/generate-icons.js（sharp）
  │   ├─► build/icon.png(512) ~ icon-16.png   → 桌面端
  │   └─► android mipmap（5密度×3变体）       → Android
  │
  ├─► scripts/build-tools.cjs make-ico
  │   └─► build/icon.ico                      → Windows 安装包

更换图标：替换 build/app-icon.png 后重新构建即可。

发布

pnpm publish-release

发布到 GitHub generic provider，通过 electron-updater 实现自动更新。
